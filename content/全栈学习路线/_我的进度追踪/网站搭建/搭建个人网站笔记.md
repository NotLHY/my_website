## 为什么写这篇笔记

这是我第一篇正式笔记，记录我把 Obsidian 笔记发布成个人网站的完整过程，方便以后重装系统或者换电脑时照着做一遍。

## 整体架构

- **Obsidian**：写笔记的地方，vault 位于 `E:\Programing\Learning_map\fullstack-journey`
- **实际发布的笔记**：只有 `全栈学习路线\_我的进度追踪` 这个子文件夹
- **Quartz 网站仓库**：`E:\Programing\Projects\my-website`（跟笔记不在同一目录）
- **连接方式**：Windows Junction（联接点），让 `my-website\content` 指向 `_我的进度追踪`
- **部署方式**：GitHub Actions 自动构建 → GitHub Pages 托管

> **重点提醒**：Obsidian 本身不提供创建 junction / 软链接的功能，这是 Windows 系统的能力（`mklink` 命令）。Obsidian 只是正常打开笔记文件夹，感知不到背后有链接。

## 第四步：把 content 换成指向笔记文件夹的 Junction 【可选，装了 Quartz Syncer 后可跳过】

> 如果用 Quartz Syncer 插件发布（见第五步），这一步可以不做，直接跳到第五步配置插件即可。这里保留作为备用方案。

先删掉自动生成的空 `content` 文件夹：

```powershell
cd E:\Programing\Projects\my-website
rmdir /s /q content
```

用 `dir` 确认 `content` 已经消失，然后建立 junction：

```powershell
mklink /J content "E:\Programing\Learning_map\fullstack-journey\全栈学习路线\_我的进度追踪"
```

成功会显示：
```
Junction created for content <<===>> E:\Programing\Learning_map\fullstack-journey\全栈学习路线\_我的进度追踪
```

验证：
```powershell
dir content
```
应该能看到 `_我的进度追踪` 里的文件列表。

**小知识**：
- Junction 不是复制，也不是快捷方式，是系统层面的路径映射，两边读写的是同一份文件
- 删除 junction 本身（`rmdir content`，不加 `/s`）不会删掉原始笔记，只是解除映射
- 路径里有中文一定要用双引号包住，避免解析出错

## 第五步：frontmatter 写法（发布/不发布控制）

> **更新**：装了 **Quartz Syncer** 插件之后，就不需要再手动建 junction 了（第四步可以跳过）。Quartz Syncer 直接通过 GitHub API 把选中的笔记推送到 Quartz 仓库，不要求笔记和仓库在同一路径下，非常适合"笔记和网站仓库不在一个文件夹"的情况。

### frontmatter 加在哪里？——文件最顶部，不是标题

frontmatter 不是笔记的标题，是整个 `.md` 文件**最开头单独的一块元数据**，在正文（包括你自己写的 `# 标题`）之前。完整示例：

```markdown
---
title: 笔记标题
tags:
  - 标签1
publish: true
---

# 这里才是正文里自己写的标题

正文内容从这里开始写……
```

一个文件里有两个"标题"概念，别搞混：
- `---` 区块里的 `title:` 是元数据，告诉 Quartz 网页标题显示什么，不会出现在正文里
- 正文里自己写的 `# 一级标题` 是给人看的，显示在网页正文顶部

**在 Obsidian 里怎么加，不用手打 YAML**：新建笔记后，把光标放在文件**最开头第一行最前面**，输入 `---` 回车，Obsidian 会自动弹出可视化的 **Properties（属性）面板**：
- 点 "+ Add property" → 输入字段名 `title`，类型选 Text，填标题
- 再加一个字段 `tags`，类型选 List
- 再加一个字段 `publish`，类型选 Checkbox，勾选✓（对应 `true`）

Obsidian 会自动生成正确格式写到文件顶部，跟正文之间有条分隔线，不需要自己记语法。

Quartz Syncer 的发布逻辑跟 Quartz 原生的 `draft` 是**反过来**的：默认所有笔记都不发布，要手动标记 `publish: true` 才会显示。这是在 Obsidian 设置 → Community Plugins → Quartz Syncer → Frontmatter 标签页里配置的（Publish key 默认叫 `publish`，"All notes publishable by default" 保持关闭）。

字段说明：

- `title`：不写的话用文件名当标题
- `tags`：Quartz 会自动生成标签页，方便分类
- `publish: true`：这篇笔记会出现在 Quartz Syncer 的"发布中心"列表里；不写或写 `false` 则保持私密，不会被推送
- `created` / `modified`：可以手动写创建、修改时间，Quartz Syncer 会自动识别这几个字段名（created/created_at/date，modified/lastmod/updated/last-modified）

### 怎么真正点击发布

1. Obsidian 左侧边栏点击 Quartz 水晶图标（或命令面板搜 "Quartz Syncer: Open publication center"）
2. 打开发布中心，会列出所有 `publish: true` 的笔记
3. 勾选要发布的笔记，点左下角 **"PUBLISH SELECTED CHANGES"**
4. 插件会自动帮你 commit 并推送到 GitHub 仓库，触发 GitHub Actions 自动构建部署

## 第八步：配置 GitHub Actions 自动部署

1. 新建文件 `.github\workflows\deploy.yml`：

```powershell
mkdir .github\workflows
```

内容：

```yaml
name: Deploy Quartz site to GitHub Pages

on:
  push:
    branches:
      - v5

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v6
        with:
          node-version: 24
      - name: Install Dependencies
        run: npm ci
      - name: Install Quartz plugins
        run: npx quartz plugin install
      - name: Build Quartz
        run: npx quartz build
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: public

  deploy:
    needs: build
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

2. GitHub 仓库页面 → **Settings → Pages → Source**，从 "Deploy from a branch" 改成 **"GitHub Actions"**
3. 推送：

```powershell
npx quartz sync
```

4. 去仓库的 **Actions** 标签页看构建进度，绿勾代表成功
5. 网站地址：`https://你的GitHub用户名.github.io/my-website`

## 排查清单

| 现象 | 排查方向 |
|---|---|
| `mklink /J` 报错找不到路径 | 检查路径、中文是否完整、双引号是否包住整条路径 |
| `dir content` 是空的 | junction 没建成功或链接错了层级 |
| 本地预览是空白页 | 笔记文件里 `draft: true`，或者文件夹里还没有 `.md` 文件 |
| GitHub Actions 跑红叉 | 点进日志看具体报错，常见是 `deploy.yml` 缩进错了 |
| Pages 显示 404 | 确认 Settings → Pages → Source 选的是 GitHub Actions |
